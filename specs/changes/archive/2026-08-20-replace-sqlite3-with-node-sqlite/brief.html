Replace native SQLite package with Node’s built-in driver

TL;DR

The pool will stop using the third-party sqlite3 native module and use Node’s built-in SQLite support instead. Uptime tracking behavior stays the same for operators and guardians; installs become simpler, and Node 22.13+ becomes the minimum.

What you'll get

  • Same uptime tick storage and /pool/uptime responses, without a native C++ addon dependency.
  • An explicit Node engine floor of 22.13 or newer.
  • An automated test suite for the storage layer so regressions are caught by npm test.

How it works

The storage module opens the same on-disk database file and runs the same SQL. Internally it uses Node’s synchronous SQLite API, then still calls the existing uptime callback on the next event-loop turn so the rest of the app does not need rewriting. 

flowchart LR
  Guardians[Guardian updates] --> App[Pool app]
  App --> Storage[Storage module]
  Storage --> Builtin[node:sqlite]
  Builtin --> File[(database.db)]
  App --> Uptime["/pool/uptime"]
  Uptime --> Storage

What changes for you

  • Deploy/run on Node ≥ 22.13.
  • You may see an experimental SQLite warning from Node until that API is marked stable — expected.
  • Run npm test to verify storage after install.

Risks and open questions

  • Built-in SQLite is still experimental in Node; a future Node major could tweak the API.
  • Database work is synchronous on the event loop; fine for current small tick queries, revisit if the store grows a lot.

Out of scope

  • Changing the database schema or uptime math.
  • Rewriting the HTTP app to async/await storage APIs.
  • Keeping a fallback to the old sqlite3 package.

Work overview

  • Storage rewrite with tests — 2 tasks
  • Smoke / wiring check — 1 task
